# INCIDENT: 2026-04-08 Threads API `since` パラメータで400

## タグ
`#project:affiliate-bot` `#category:api` `#severity:low`

## 症状
- `GET .../v1.0/{user_id}/threads?since=<timestamp>&...` が**常に400**
- `since` / `before` / `after` を付けるとエラー
- 時刻範囲フィルタが APIサイドで効かない

## 真因

**層: 外部API（Threads Graph API の非対応パラメータ）**

- Threads API の `/threads` endpoint は **`since`, `before`, `after` 非対応**
- サポートされているのは実質 `limit:10〜100` のみ
- Instagram Graph API の前身から `since` を期待すると失敗する

## 復旧手順

1. `since` 等のパラメータを使わない
2. `limit=100` で最大数取得 → **クライアント側で timestamp フィルタ**
3. 時刻範囲が必要な場合:
   ```python
   resp = requests.get(
       f"{BASE}/v1.0/{user_id}/threads",
       params={"fields": "id,text,timestamp", "limit": 100, "access_token": token},
   )
   cutoff = datetime.now(timezone.utc) - timedelta(days=7)
   filtered = [p for p in resp.json().get("data", [])
               if datetime.fromisoformat(p["timestamp"].replace("Z","+00:00")) >= cutoff]
   ```

## 学び

1. **API仕様は実証主義**（公式docよりも実API応答を信じる）
2. Threads APIで使える主要paramは `fields`, `limit`, `access_token` のみと覚えておく
3. 時刻系フィルタは全てクライアント側で実装する想定にする
